# Как устроен Deckbook

Deckbook — не библиотека утилитарных классов. Стилизованы **сами HTML-теги**,
а поверх лежит короткий список одноцелевых классов. Никакого Tailwind,
CSS-in-JS, тем и пропсов оформления: `<button>` уже выглядит как кнопка,
`<input>` — как поле, `<summary>` — как ссылка-действие.

## Обязательное: система только светлая

Направление «Тихий лист»: тёплая бумага вместо тёмного фона, иерархия задаётся
**подложкой**, а не рамками. `:root` задаёт `color-scheme: light`, `body` —
`background: var(--bg)`. Любой макет обязан рендериться на этом фоне: тёмный
текст (`--text: #2c2a26`) на тёмном фоне пропадёт. Если корневой узел макета
не `<body>`, задайте фон вручную:

```jsx
<div style={{ background: "var(--bg)", color: "var(--text)" }}>…</div>
```

Рамок в макете почти нет: карточка — это `--panel` на `--bg` без бордера,
разделитель внутри карточки — `--rule`, рамка бывает только у поля (`--field`).

## Токены

| Токен | Что это |
|---|---|
| `--bg` | лист: фон страницы, фон полей |
| `--panel` | подложка: шапка, карточки, `<pre>` |
| `--line` | внешняя рамка кадра |
| `--field` | рамка поля ввода |
| `--rule` | разделитель строк внутри карточки |
| `--text`, `--ink` | основной текст и текст длинных абзацев |
| `--muted`, `--dim` | вторичный текст и погашенное (отменённое) |
| `--accent`, `--accent-ink`, `--accent-bg` | зелёный: кнопки, важные ссылки, зелёная плашка |
| `--dot`, `--dot-done`, `--dot-line` | точка статуса: в работе / готова / открыта |
| `--danger`, `--danger-bg`, `--danger-line` | ошибки и разрушающие действия |

Обращаться через `var(--…)`; новых цветов не заводить.

## Классы — весь словарь

| Класс | Для чего |
|---|---|
| `.card` | подложка без рамки; `.card.tight` — под список строк |
| `.list` + `.item` | строки списка с разделителем; `.grow` — растянуть ячейку |
| `.kids` | вложенный уровень дерева: отступ и левая линия |
| `.dot` | точка статуса; модификаторы `.in_progress`, `.done`, `.live` |
| `.bar` | горизонтальный ряд; `.spacer` — распорка внутри него |
| `.head` | заголовок раздела: `<h2>` + счётчик + действия справа |
| `.rule` | линия-разделитель внутри карточки с отступами |
| `.row` (на `<form>`) | ряд полей и кнопок с переносом |
| `.row.copy` | то же вне формы (используется в `CopyField`) |
| `.snippet` | `<pre>` с командой + кнопка справа (`CopySnippet`) |
| `.act` | ссылка-действие: работает и на `<a>`, и на `<button>`, и на `<summary>`; `.go` — зелёная, `.bad` — красная |
| `.plain` (на `<button>`) | вторичная кнопка: рамка вместо заливки; `.plain.bad` — красная мелкая |
| `.icon` (на `<button>`) | квадратная кнопка 34×34 под один значок |
| `.muted`, `.bad`, `.off` | вторичный, тревожный и погашенный текст |
| `.crumbs` | хлебные крошки над заголовком |
| `.error` | красная плашка ошибки (используется в `Banner`) |
| `.notice` | зелёная плашка важного разового сообщения; `.slim` — в одну строку |
| `.feed` | лента задачи; `.system` — служебная запись одной строкой |
| `.steps` | нумерованные шаги шаблона; `.n` — номер |
| `.markdown` | контейнер отрендеренного markdown (ставит сам `Markdown`) |
| `.top` + `.inner` | шапка страницы и её внутренний ряд — размечаются вручную, см. «Каркас страницы» |
| `.brand` | ссылка-логотип в шапке: `<Logo />` плюс слово «Deckbook» |
| `.here` | активная ссылка навигации; `ProjectNav` проставляет её сам |

Своих имён классов не придумывать: незнакомый класс не имеет стилей вовсе.
Нужна раскладка, которой нет в таблице, — это inline `style` с токенами.

## Каркас страницы

Шапка живёт **снаружи** `<main>`; `<main>` сам центрируется и ограничен
1000px с полями по 40px. Раздел открывается компонентом `<Head>`.

Готового компонента шапки в системе нет — она размечается вручную классами
`.top` и `.inner`, как ниже. Внутрь ставится `<ProjectNav>`, `.spacer`
раздвигает левую и правую группы.

```jsx
const { Logo, ProjectNav, Banner, Head, Icon, Reveal } = window.Deckbook;

<>
  <header className="top">
    <div className="inner">
      <a className="brand" href="/"><Logo />Deckbook</a>
      <ProjectNav slug="deckbook" at="tokens" />
      <span className="spacer" />
      <a className="act" href="/my-tasks"><Icon name="check" />Мои задачи</a>
    </div>
  </header>
  <main>
    <h1>Токены</h1>
    <Banner error={error} />
    <Head title="Выпущенные" count={2}>
      <Reveal label="выпустить токен" icon="plus" drop>
        <form className="row" method="post" action="/api/tokens">
          <input type="text" name="name" placeholder="Имя агента" required />
          <button type="submit"><Icon name="plus" />Выпустить</button>
        </form>
      </Reveal>
    </Head>
    <div className="card tight list">…</div>
  </main>
</>
```

Мутации — обычные `<form method="post">` на Route Handler в `/api/*`, без
клиентского состояния. `Back` кладёт в форму скрытый адрес возврата.

## Второстепенные действия

Всё, что не главное на экране, живёт под `<Reveal>` — нативный `<details>`,
в покое выглядящий ссылкой. `drop` раскрывает форму поповером поверх
раскладки (для рядов), без него — раздвигает поток. Клиентского состояния
по-прежнему нет.

## Что читать

- `styles.css` и `_ds_bundle.css` — настоящий и единственный источник стилей.
- `components/general/<Name>/<Name>.prompt.md` — пропсы и примеры компонента.
- Шрифты не поставляются: системный стек `ui-sans-serif, system-ui`,
  для кода — `ui-monospace, SFMono-Regular, Menlo`.
- Значки — `<Icon name="…" />`, штриховые по 14px; все 19 имён перечислены
  в `components/general/Icon/Icon.d.ts`, а карточка `Icon` показывает набор.
- `ConfirmButton`, `CopyField`, `CopySnippet` работают в браузере
  (`confirm()`, `navigator.clipboard`) — только на клиенте.
- Форматтеров дат и склонений в бандле нет — только компоненты. Дату
  форматируйте сами и передавайте готовой строкой.
