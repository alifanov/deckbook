# Как устроен Deckbook

Deckbook — не библиотека утилитарных классов. Стилизованы **сами HTML-теги**,
а поверх лежит короткий список одноцелевых классов. Никакого Tailwind,
CSS-in-JS, тем и пропсов оформления: `<button>` уже выглядит как кнопка,
`<table>` — как таблица, `<input>` — как поле.

## Обязательное: система только тёмная

`:root` задаёт `color-scheme: dark`, а `body` — `background: var(--bg)`.
Любой макет обязан рендериться на этом фоне, иначе светлый текст
(`--text: #e6e8ec`) окажется на светлом фоне и пропадёт. Если корневой узел
макета не `<body>`, задайте фон вручную:

```jsx
<div style={{ background: "var(--bg)", color: "var(--text)" }}>…</div>
```

## Токены

Все семь, больше нет: `--bg` (фон страницы), `--panel` (шапка, карточки,
`<pre>`), `--line` (все рамки и разделители), `--text`, `--muted` (вторичный
текст), `--accent` (ссылки, фокус, активный статус), `--danger` (ошибки,
разрушающие действия). Обращаться через `var(--…)`; новых цветов не заводить.

## Классы — весь словарь

| Класс | Для чего |
|---|---|
| `.card` | блок с фоном `--panel` и рамкой: элемент списка, документ |
| `.row` (на `<form>`) | горизонтальный ряд полей и кнопок с переносом |
| `.row.copy` | то же вне формы (используется в `CopyField`) |
| `.snippet` | `<pre>` с командой + кнопка справа (используется в `CopySnippet`) |
| `.muted` | вторичный текст 13px цветом `--muted` |
| `.error` | красная рамка — блок ошибки (используется в `Banner`) |
| `.notice` | акцентная рамка — важное разовое сообщение |
| `.status` | пилюля статуса; модификаторы `.in_progress`, `.done`, `.cancelled` |
| `.tree` | `<ul>` вложенного списка задач с левой линией |
| `.feed-entry` | запись ленты; `.system` — служебная, курсивом |
| `.markdown` | контейнер отрендеренного markdown |
| `.danger` (на `<button>`) | разрушающее действие: рамка и текст краснеют на hover |
| `.brand`, `.inner`, `.spacer`, `.top` | внутренности `Header`, вручную не используются |

Своих имён классов не придумывать: незнакомый класс не имеет стилей вовсе.
Нужна раскладка, которой нет в таблице, — это inline `style` с токенами.

## Каркас страницы

`<Header>` живёт **снаружи** `<main>`; `<main>` сам центрируется и ограничен
900px. Заголовок раздела — `<h2>` (он рендерится капслоком цветом `--muted`).

```jsx
const { Header, ProjectNav, Banner } = window.Deckbook;

<>
  <Header><ProjectNav slug="deckbook" /></Header>
  <main>
    <h1>Токены проекта «Deckbook»</h1>
    <Banner error={error} />
    <h2>Выпустить токен</h2>
    <form className="row" method="post" action="/api/tokens">
      <input type="text" name="name" placeholder="Имя агента" required />
      <button type="submit">Выпустить</button>
    </form>
  </main>
</>
```

Мутации — обычные `<form method="post">` на Route Handler в `/api/*`, без
клиентского состояния. `Back` кладёт в форму скрытый адрес возврата.

## Что читать

- `styles.css` и `_ds_bundle.css` — настоящий и единственный источник стилей.
- `components/general/<Name>/<Name>.prompt.md` — пропсы и примеры компонента.
- Шрифты не поставляются: системный стек `ui-sans-serif, system-ui`,
  для кода — `ui-monospace, SFMono-Regular, Menlo`.
- `ConfirmButton`, `CopyField`, `CopySnippet` работают в браузере
  (`confirm()`, `navigator.clipboard`) — только на клиенте.
- Кроме компонентов, `window.Deckbook.when(date)` форматирует дату в `ru-RU`
  и отдаёт «—» для пустого значения.
