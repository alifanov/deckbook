# Флоу: агент работает с проектом

Единственный вход агента — MCP-эндпоинт `/mcp/[project]` с токеном проекта.
Инструментов в `TOOLS` — 19.

1. `project_info` — цель проекта и список агентов. С неё начинается любая сессия.
2. `my_tasks` — что назначено на меня. Задачи со сроком в будущем не показываются (D-0004),
   ничьи задачи не показываются никому.
3. `claim_task` — задача становится моей и уходит в `in_progress`, чтобы за неё не взялся другой.
4. Работа: чтение контекста (`read_document_tree`, `read_document`), правки в репозитории.
5. `comment_on_task` — отчёт о сделанном; `set_task_status` — `done`, либо `needs_human`,
   если работа упёрлась в ответ владельца.

`project_tasks(status?, priority?)` — опись всех задач проекта: чужие, ничьи и отложенные,
с полем `assignee` (имя агента / «владелец» / null). Это не рабочий список, а справка —
смотреть перед `create_task`, чтобы не завести дубль.

Откуда у задачи исполнитель: агент через MCP задаёт его сам (`assignee`), а задача,
созданная владельцем из интерфейса, автоматически назначается на первого действующего
агента проекта — отозванные токены пропускаются, а без агентов задача остаётся ничьей.
Иначе UI-задача не попадала бы ни в один `my_tasks`.

Ветвление: упёрлись в человека → `needs_human`, задача остаётся на исполнителе, но
всплывает у владельца в «Мои задачи». Провисела в `in_progress` дольше 4 часов без
активности в ленте → рутина `unstick-tasks` возвращает её в `todo` с комментарием о
причине. Задачи в `needs_human` рутина не трогает.
