### Ревью кода

Смотрели: `src/auth.ts`, `src/session.ts`, `src/middleware.ts`, `src/http.ts`,
`src/domain/tokens.ts`, `src/mcp/server.ts`, `src/mcp/tools.ts`, все `src/app/api/**`.

Держит:

- **Граница проекта у агента (ADR-0003)** — каждый MCP-инструмент, принимающий чужой id
  (`read_task`, `set_task_status`, `move_task`, `read_document`, `write_document`, `move_document`, …),
  сначала зовёт `requireTaskInProject` / `requireDocumentInProject`. Токен проекта A не достанет
  задачу или документ проекта B. Проверены все 27 инструментов — пропусков нет.
- **Токены агентов** — в базе только `sha256`, значение показывается один раз через
  одноразовую куку, `revokedAt` проверяется при каждом запросе, слаг из адреса сверяется
  с проектом токена.
- **Пароль владельца** — `scrypt` с солью, сравнение постоянного времени, в базе только хеш.
- **Сессия** — HMAC поверх `срок:поколение`, `httpOnly`, `sameSite=lax`; выход поднимает
  поколение и гасит все выданные куки разом.
- **Инъекции** — весь доступ к данным через Prisma, сырого SQL нет. Markdown рендерится
  `markdown-it` с `html: false` — XSS через описание задачи или документ не проходит.
- **Секреты** — `.env` в `.gitignore`, в индексе только `.env.example` с плейсхолдерами.

Найденные дыры:

1. **Security-заголовков нет вообще.** Ни `next.config.ts`, ни `middleware.ts`, ни прокси
   не отдают CSP, HSTS, `X-Frame-Options`/`frame-ancestors`, `Referrer-Policy`,
   `X-Content-Type-Options`. Интерфейс владельца открыт для кликджекинга, второго рубежа
   против XSS нет.
2. **Вход не ограничен по числу попыток.** `POST /api/session` (`src/app/api/session/route.ts`)
   зовёт `verifyPassword` без счётчика, задержки и блокировки. Один пароль открывает всё —
   задачи, документы, выпуск агентских токенов.
3. **Авторизация живёт только в middleware.** `src/app/api/{tasks,documents,projects,tokens}/route.ts`
   своей проверки сессии не делают — целиком полагаются на `src/middleware.ts`. Класс
   обходов middleware в Next.js уже случался (CVE-2025-29927), а сам `matcher`
   `/((?!login|api/session|mcp|_next|favicon.ico).*)` исключает пути по префиксу без границы.
4. **Открытый редирект** в `formHandler` (`src/http.ts:20`): поле формы `back` уходит в
   `Location` без проверки, что это внутренний путь. `sameSite=lax` мешает раскрутить это
   кросс-сайтом, поэтому low.

### Live-проверка

Прод по адресу из `state/product/product` (`http://…sslip.io:3000`) **не отвечает** —
соединение на 3000 не устанавливается. Приложение фактически стоит за Traefik на 80/443:

- `http://…sslip.io/` → 308 на https ✅
- `https://…sslip.io/login` → **HTTP 503**, приложение не отдаёт ответ ❌
- Сертификат: `CN=TRAEFIK DEFAULT CERT`, самоподписанный, выпущен 2026-08-04 ❌ —
  валидного TLS нет, `secure`-кука и HSTS в такой конфигурации бессмысленны.

Чеклист заголовков снять не удалось — до приложения запрос не доходит, 503 отдаёт прокси.
Статически подтверждено, что в коде заголовки не выставляются ни для одного маршрута:

| Заголовок | Статус |
|---|---|
| Content-Security-Policy | ❌ не задан |
| Strict-Transport-Security | ❌ не задан |
| X-Frame-Options / frame-ancestors | ❌ не задан |
| X-Content-Type-Options | ❌ не задан в приложении (приходит только от страницы ошибки Traefik) |
| Referrer-Policy | ❌ не задан |
| Флаги куки `/api/auth/session` | не проверить — маршрута нет, сессия на `POST /api/session`; в коде `httpOnly` + `sameSite=lax` + `secure` в production ✅ |

одном middleware.
